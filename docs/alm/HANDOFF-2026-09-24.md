## What exists and works

- Power Automate flows in ADMIN, solution `ALMPipeline` (publisher almspike, prefix alm):
  - **ALM C1 - Deploy (parent)**: runs the stages Prechecks → Export (managed from DEV, archive ZIP to ALM-Admin `Solutions/`) → Import → PostImport, then writes a log to `DeploymentLogs/`.
  - **ALM C2 - Import (child)**: builds ComponentParameters from `ALMConnections` + `ALMVariables` and imports the archived ZIP.
  - **ALM C3 - Post-import (child)**: checks the connection bindings, sets the variable values, and turns on the solution's flows.
  - **ALM Setup - SharePoint config**: helper for scripted config changes, Demo→TEST only. It's off; `pipeline.sp_setup` turns it on at deploy.
- Flows are defined as code in `pipeline/` (Python stdlib). `python3 -m pipeline.deploy` rebuilds and deploys them. 59 unit tests.
- Config lives in ALM-Admin SharePoint: `ALMConfig` (switches `RunImport`, `RunPostImport`, `RunShare`), `ALMConnections`, `ALMVariables`.
- Live acceptance tests 1–6 passed (see the runbook table).
